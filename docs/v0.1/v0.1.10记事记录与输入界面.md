# v0.1.10 记事记录与输入界面

**状态：已确认**

## 背景与目标

把状态球输入框从交互测试改为可用的本地记录入口。提交后在主窗口分割线下展示记录，并开始下一段计时。保留日期和当时的状态信息，为后续按日期浏览提供数据。

## 范围与行为

- 点击主窗口或悬浮窗的状态球打开输入框。有效文本通过回车或「提交」保存。保存成功后关闭输入框、更新主窗口记录列表，并将经过时间清零，从初始颜色开始下一轮计时。
- 每条记录保存独立标识、文本、记录时的系统日期和时间、当时的状态球颜色，以及本轮经过时长。日期以记录时的本地日期为准。
- 分割线下方按草图展示记录。每行左侧是记录时状态球颜色的竖条，中间显示记录时间 `HH:mm`，右侧显示文本。将鼠标移到时间上时显示本轮耗时。
- 支持新增记录和修改已有记录。修改后将结果持久化。
- 输入框使用紧凑白色面板，统一输入框和按钮的高度、间距和焦点样式。移除「测试输入」标题文案。
- 非提交关闭新增输入窗口后，未提交文本在当前进程内保留 1 分钟。在任一状态球入口重新打开时恢复草稿，超时或成功提交后清除。
- 优化现有图标在任务栏和托盘中的小尺寸显示效果。

## 非目标与兼容边界

本轮提供日期数据，按日期筛选和日历浏览留待后续需求。记录保存在本机当前 Windows 用户下。已有颜色时间表、悬浮位置和启动设置继续可用，首次升级时记录列表为空。

## 已确认事项

| 问题 | 确认结论 | 理由 |
| --- | --- | --- |
| 新增时何时重置计时？保存失败怎么处理？ | 仅在非空文本成功写入后重置。保存前取同一时刻的日期、时间、颜色和耗时。空白内容不新增。写入失败时保留输入并提示，计时继续。 | 确保记录所示颜色和耗时来自同一段，避免用户输入丢失。 |
| 如何编辑已有记录？ | 双击记录或选中后按 Enter，打开同样的输入框并填入原文。保存只修改正文，保留原日期、时间、颜色和耗时，当前计时继续。 | 保留原记录的历史信息，也避免修正错字影响正在计时的活动。 |
| 默认显示哪些记录？ | 本轮显示全部已保存记录，最新新增的记录排在末尾。加载和新增后滚动到末尾，长文本自动换行。悬停时间时，耗时显示到整分钟。 | 可直接查看最新记录，保留从上到下的记录顺序。 |
| 输入框移除标题后是否保留拖动？ | 保留顶部细窄拖动区，用短横线标明拖动位置。下方只放输入框和「提交」按钮。回车提交，Esc 或点击外部关闭。 | 保留拖动能力，同时让输入和提交成为视觉重点。 |
| 任务栏和托盘图标是否提供大小设置？ | 自主优化 ICO 的小尺寸版本。放大状态球和涟漪，减少透明留白和细装饰，并检查任务栏和托盘的实际显示。 | 两处图标的显示区域由 Windows 决定。优化图案在区域内的占比，比增加软件内的大小滑块更直接。 |

## 验收条件

1. 从两处状态球提交有效文本后，主窗口分割线下新增一行，计时归零并从初始色重新开始。空白或写入失败时列表和计时保持原状。
2. 记录行按草图显示颜色条、提交时的时分和正文。最新记录在末尾，加载和新增后自动滚动到末尾。耗时以整分钟显示，颜色条在后续变色时保持记录时颜色。
3. 修改正文后仍保留原时间、日期、颜色和耗时，当前计时继续。关闭并重启应用后，新建和修改的记录都可读取，跨午夜的记录保留各自日期。
4. 输入框没有「测试输入」文字，保留拖动、键盘提交和关闭操作。检查资源管理器、任务栏和托盘的小尺寸图标，球体与涟漪应清晰可辨。
5. 非提交关闭输入框后，在 1 分钟内从任一状态球重新打开可恢复原文。超过 1 分钟或成功提交后再次打开时输入为空。

## 技术设计

- 使用当前用户本地应用数据目录下的 JSON 文件保存记录。每次写入通过独占写锁串行化，重新读取磁盘数据后在同目录写入临时文件并替换正式文件。
- 保存带时区偏移的记录时间，日期和时间直接取记录时的本地值。新增记录在同一时刻计算颜色和耗时，成功保存后重置现有计时和提醒状态。修改正文沿用原元数据。
- 草稿仅保留在进程内，使用单调时钟计算 1 分钟有效期。新增和修改共用输入窗，草稿仅用于状态球新增入口。

## 实施与验收
