# v0.1.16 手动计时重置与休眠后重置

**状态：已确认**

## 背景与目标

用户可以随时开始新的计时段。Windows 从长时间睡眠或休眠中恢复时，应用自动开始新的计时段。

## 范围与行为

- 在主窗口悬浮窗开关右侧添加「重置计时」图标按钮，悬停显示「重置计时」。悬浮窗开启或关闭时，重置按钮均可使用。
- 主窗口按钮按住时显示长按进度，持续满 0.5 秒后直接重置。短按并在按钮内松开时弹出确认。
- 在状态球悬浮窗右键菜单中添加「重置计时」。选择后弹出确认。
- 应用在 Windows 恢复时检查实际休眠时长。超过 60 分钟时重置一次，等于或低于 60 分钟时继续计时。应用保留在托盘时也适用。
- 自动判断基于实际休眠时长。仅锁屏、系统改时、应用卡顿或正常运行超过 60 分钟时继续计时。
- 三个入口采用一致的重置行为。主窗口经过时间归零，主窗口与悬浮窗的状态球恢复初始色，从新起点应用颜色时间表。

## 非目标与兼容边界

沿用 Windows、.NET 8 和 WPF。已有记录、分类、颜色规则和设置继续可用。自动重置只改变当前计时段，不新增历史记录。

## 已确认事项

- Windows 本次实际休眠超过 60 分钟时，恢复后重置计时一次。以恢复通知为主要检查入口，现有计时刷新作为兜底。
- 比较两次采样间 `GetTickCount64` 与 `QueryUnbiasedInterruptTime` 的增量差，统一单位后计算休眠时间。每次检查及手动重置后更新基准，已处理的休眠间隔不重复触发。首次采样仅建立基准。
- 悬浮窗菜单或主窗口短按弹出「是否重置计时？」确认框，默认取消。键盘激活主窗口按钮时也走确认路径。长按进度到 0.5 秒时只执行一次，松开时不再弹出确认。触发前移出按钮或失去按压状态时，清除进度。手动重置不新增记录，也不修改历史或输入草稿。

- 重置时清除旧段待补播提醒，并重新计算新一段的提醒时间。重置本身不播放定位涟漪。

## 验收条件

1. 主窗口的重置按钮在悬浮窗开关右侧，悬停文字准确。悬浮窗右键菜单中显示同名操作。
2. 验证悬浮窗右键菜单、主窗口短按及键盘激活均弹出确认，取消后计时继续，确认后计时归零。
3. 长按主窗口按钮时能看到进度反馈，满 0.5 秒后只重置一次，松开时不弹确认。提前移出按钮后不触发。
4. 分别模拟实际休眠 59 分 59 秒、60 分钟和 60 分 1 秒。仅第三种自动重置。验证应用保留在托盘时也能处理恢复。
5. 模拟漏收恢复通知，确认计时刷新可补做检查。同一休眠间隔经过通知和刷新检查时，只重置一次。
6. 验证仅锁屏、应用卡顿、系统改时及正常运行超过 60 分钟均不触发自动重置。重置后两处状态球回到初始色，已有记录和草稿保持原状。

## 技术设计

- 主窗口使用单调计时计算按压进度。到达 500 毫秒时消费本次按压，短按与键盘激活走确认入口。悬浮窗菜单共用确认逻辑。
- 主实例订阅 Windows 电源恢复通知，并在现有计时刷新中补查。采样和基准更新都在 UI 调度器串行处理。三个重置入口共用计时段重置逻辑。

## 实施与验收

主窗口重置按钮显示按压进度，长按时只重置一次。悬浮窗菜单和主窗口短按、键盘激活共用默认取消的确认框。计时重置同时刷新状态球初始色和提醒基准。电源恢复通知与计时刷新使用同一休眠检测器，并会忽略晚到的旧采样。
