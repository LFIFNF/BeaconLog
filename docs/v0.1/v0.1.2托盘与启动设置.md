# 托盘与启动设置

**状态：已确认**

## 背景与目标

用户可以关闭主窗口并让 BeaconLog 继续在 Windows 通知区域运行，也可以在设置中选择是否随 Windows 登录启动、是否在启动时直接进入托盘。

## 范围与行为

- 点击主窗口的系统关闭按钮后，隐藏主窗口并留在托盘中，应用继续运行。
- 软件启动时立即创建托盘图标。主窗口可见、最小化、隐藏，或应用静默启动时，托盘图标均保持可用。
- 在设置窗口中新增「开机自启」和「静默启动」两个选项。「开机自启」控制当前用户登录 Windows 后是否自动运行 BeaconLog。「静默启动」开启时，启动后直接进入托盘，主窗口不出现。
- 互换主窗口中「打开悬浮窗」与「调整悬浮窗」的位置。顶部从左到右依次为状态球、「打开悬浮窗」、「调整悬浮窗」、「设置」。

## 非目标与兼容边界

本轮的悬浮窗调整范围仅限两个入口的位置，记事和状态球计时功能留待后续需求。兼容现有 Windows、.NET 8 和 WPF 环境。从 v0.1.1 升级时按最终确认的默认值初始化新增选项。

## 已确认事项

| 问题 | 确认结论 | 理由 |
| --- | --- | --- |
| 托盘里如何恢复窗口和退出应用？ | 双击托盘图标恢复主窗口。右键菜单提供「打开主窗口」和「退出」。点击「退出」后关闭应用及其所有窗口，并移除托盘图标。 | 保留常见的恢复和彻底退出路径。 |
| 两项设置的默认值和生效方式是什么？ | 默认均关闭。切换后立即保存并跨重启保留。「开机自启」影响后续登录，「静默启动」影响下次启动。 | 升级后保留既有启动体验，用户无需额外点击保存。 |
| 手动启动是否也遵循静默设置？ | 手动启动和开机自启都遵循同一个静默启动设置。 | 两个启动入口的行为一致，也可以单独使用静默启动。 |
| 设置窗口打开时，关闭主窗口如何处理？ | 返回托盘时同时关闭设置窗口，恢复后可从主窗口再次打开。 | 避免主窗口隐藏后仍留下设置窗口。 |

## 验收条件

1. 主窗口顶部的两个悬浮窗入口已互换位置，状态球和设置入口仍可见。
2. 点击主窗口关闭按钮后，主窗口消失、进程继续运行，托盘图标可见。
3. 两项设置可独立切换。开启静默启动后重新启动，主窗口不闪现，可通过托盘恢复。关闭静默启动后重新启动，主窗口正常显示。
4. 开启开机自启后，当前用户下次登录 Windows 时应用自动运行。关闭后，下次登录时不自动运行。
5. 验证选项默认关闭、跨重启保留、托盘恢复和退出，以及设置窗口打开时返回托盘的行为。
6. 正常启动后主窗口与托盘图标同时可见。静默启动后托盘图标可用，主窗口不出现。

## 技术设计

由应用在启动时持有 Windows 通知区域图标并负责显式退出。关闭主窗口时先关闭设置窗口，再隐藏主窗口。静默启动时跳过首次显示，退出时释放托盘资源。

开机自启使用当前用户的 Windows Run 项，设置界面直接以该项为准。静默启动保存在当前用户的 BeaconLog 注册表项中。写入失败时恢复控件原值并提示。
