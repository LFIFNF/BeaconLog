# 状态球调整入口与静默启动范围

**状态：已确认**

## 背景与目标

新增「调整状态球」窗口入口，并调整 v0.1.2 的静默启动规则，使用户手动打开 BeaconLog 时始终看到主窗口。

## 范围与行为

- 将主窗口的「调整悬浮窗」按钮改名为「调整状态球」。点击后打开独立的调整窗口。
- 「静默启动」仅在 Windows 登录后由开机自启启动 BeaconLog 时生效。开机自启触发且静默启动开启时，只显示托盘图标。开机自启触发且静默启动关闭时，显示主窗口和托盘图标。
- 手动启动始终打开主窗口，与两项启动设置的勾选状态无关。托盘图标仍随应用启动创建。
- 在「静默启动」选项下方显示说明：「仅在开机自启时生效。手动启动始终打开主窗口。」

## 非目标与兼容边界

本轮范围限于调整窗口入口和启动行为。「打开悬浮窗」及悬浮窗本体的功能留待后续需求。沿用 Windows、.NET 8 和 WPF。升级时保留已保存的两个开关值。已有开机自启登记也应遵循新规则，用户无需重新勾选设置。

| 问题 | 确认结论 | 理由 |
| --- | --- | --- |
| 调整窗口首版显示什么？ | 使用白色空白内容区，标题为「调整状态球」，保留系统关闭按钮。 | 当前尚未定义调整项，可先验收入口。 |
| 调整窗口如何处理重复打开和主窗口隐藏？ | 沿用设置窗口的行为。使用非模态单实例，重复点击时激活已有窗口，关闭后可重新打开。主窗口隐藏到托盘时同时关闭调整窗口。 | 两个辅助窗口的交互保持一致，返回托盘时桌面不留窗口。 |
| 开机自启关闭时，静默启动选项是否可修改？ | 仍可修改和保存，说明文字始终可见。 | 用户可以提前设置偏好，开启自启后该偏好自动生效。 |
| 应用已在托盘运行时，用户再次手动启动会发生什么？ | 恢复并激活已有主窗口，保留一个应用实例和一个托盘图标。 | 用户可以从原启动入口返回主界面，避免重复运行。 |

## 验收条件

1. 点击「调整状态球」后出现同名独立窗口。窗口内容和生命周期符合确认结论。
2. 「静默启动」旁显示适用范围说明。静默启动开关开启或关闭时，手动启动均显示主窗口和托盘图标。
3. 开机自启和静默启动均开启时，登录 Windows 后只显示托盘图标，主窗口不闪现。仅开启开机自启时，登录后显示主窗口和托盘图标。
4. 关闭开机自启后，登录 Windows 时应用不自动启动。升级后两个选项的已保存值保留，原有自启登记按新规则生效。
5. 验证应用已在托盘时再次手动启动的行为符合确认结论。

## 技术设计

- 主窗口分别管理设置和状态球调整窗口。两个窗口均为非模态单实例，返回托盘时一起关闭。
- 开机自启登记通过专用命令行参数标记来源。首次运行新版时更新旧版登记，保留已保存的启动偏好。首次通过无参数的旧版登记启动新版时，按普通启动显示主窗口，更新后的登记从下一次登录起生效。
- 使用当前用户和 Windows 会话范围内的命名互斥对象与事件协调实例。手动启动的后续进程通过事件通知首个实例恢复主窗口。
