# v0.1.4 状态球外观与悬浮窗

**状态：已确认**

## 背景与目标

用户可以在「调整状态球」窗口修改状态球的大小和颜色，并在主窗口即时查看效果。「打开悬浮窗」用于在桌面上单独显示状态球。

## 范围与行为

- 在「调整状态球」窗口加入大小和颜色控件。拖动大小滑块或选择颜色后，主窗口的状态球实时更新，无需关闭调整窗口或点击「应用」。
- 将主窗口的「打开悬浮窗」改为可操作的按钮。点击后打开显示状态球的独立悬浮窗。
- 状态球的大小以彩色圆球的直径为准。主窗口中的预览需要适应调整后的大小，避免裁切圆球或遮挡其他入口。
- 在「设置」中添加「软件启动时打开悬浮窗」。默认关闭，修改后立即保存，下次启动生效。开启后，正常启动和静默启动都会打开悬浮窗。静默启动时主窗口仍保持隐藏。

## 非目标与兼容边界

本轮仅调整状态球外观与悬浮显示。记事功能、按时间间隔切换颜色和颜色规则配置留待后续需求。沿用 Windows、.NET 8 和 WPF。已有安装首次使用时采用当前的青色和 18 DIP 圆球直径作为默认值。

## 已确认事项

| 问题 | 确认结论 | 理由 |
| --- | --- | --- |
| 大小和颜色提供哪些选项？ | 大小使用 12–48 DIP 的整数滑块，显示当前数值。颜色提供常用色板，也可输入六位十六进制颜色（例如 `#08A9C1`）。输入完整有效后即预览，无效输入保留上次有效颜色并显示提示。 | 常用值容易选择，也支持精确设置。限定范围便于保证主窗口布局稳定。 |
| 外观何时保存？悬浮窗是否同步？ | 有效调整即时应用，主窗口与已打开的悬浮窗使用同一份外观。关闭「调整状态球」后保留结果，重启后继续使用。 | 两处显示一致，用户只需设置一次。 |
| 悬浮窗如何显示、移动和关闭？ | 首版只显示状态球，使用无边框、置顶式窗口，不单独显示任务栏按钮。按住圆球可拖动。右键圆球提供「关闭悬浮窗」，关闭后可从主窗口再次打开。悬浮窗已打开时，重复点击「打开悬浮窗」只唤回已有窗口。 | 状态球可以停在用户视线内，且有明确的移动和关闭方式。 |
| 主窗口返回托盘或应用重启时如何处理悬浮窗？ | 主窗口返回托盘时，已打开的悬浮窗继续显示。应用退出时关闭悬浮窗。下次启动根据「软件启动时打开悬浮窗」决定是否显示。每次新建时默认出现在主窗口所在屏幕工作区右下方。静默启动时使用主屏幕。位置不记忆。 | 用户可只留状态球在桌面，也能预期下次启动后的界面。 |

## 验收条件

1. 打开「调整状态球」后能修改大小和颜色。每次有效修改都即时反映在主窗口圆球上。最小和最大尺寸均完整显示，顶部按钮可用。
2. 点击「打开悬浮窗」后出现独立的状态球悬浮窗。按钮重复点击、窗口移动和关闭符合最终确认的行为。
3. 验证两处状态球是否按确认的规则同步，并检查无效颜色输入、首次默认值和重启后外观。
4. 验证主窗口返回托盘、应用退出及重新启动时，悬浮窗行为符合确认结论。
5. 「软件启动时打开悬浮窗」默认关闭。开启后重新启动，正常和静默启动都显示悬浮窗。关闭选项后重启，悬浮窗不自动打开。

## 技术设计

- 主窗口和悬浮窗绑定到同一个状态球外观对象。外观保存到当前用户的 BeaconLog 设置，保存成功后更新绑定，旧安装缺少对应值时使用默认外观。
- 由应用管理独立的悬浮窗实例。悬浮窗不从属于主窗口，因此主窗口返回托盘时仍可见。应用退出时由 WPF 关闭。

## 实施与验收

已实现滑块、六色预设、十六进制输入、两处实时预览和外观持久化。悬浮窗由应用管理，启动选项默认关闭。悬浮窗默认位置为最大圆球保留了空间，便于原地调大。
