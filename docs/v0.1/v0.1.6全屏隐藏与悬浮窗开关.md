# v0.1.6 全屏隐藏与悬浮窗开关

**状态：已确认**

## 背景与目标

状态球悬浮窗会置顶显示。观看全屏视频或运行全屏游戏时，应暂时隐藏状态球，退出全屏后自动恢复。主窗口需要提供直接关闭悬浮窗的入口，并统一状态球背景层的透明度。

## 范围与行为

- 在「设置」中新增「全屏时隐藏」，默认开启，切换后立即生效并保存。检测到全屏视频或全屏游戏时，隐藏已打开的状态球悬浮窗及正在播放的定位提示。退出全屏后恢复悬浮窗。关闭此选项时，悬浮窗按用户当前的打开或关闭状态显示。
- 悬浮窗打开后，主窗口按钮文案改为「关闭悬浮窗」，点击后关闭窗口并恢复为「打开悬浮窗」。从悬浮窗右键菜单关闭时，按钮也同步恢复。
- 主窗口预览和悬浮窗的背景层均固定为 50% 透明度。移除「调整状态球」中的透明度控件。背景层仍随球体大小和颜色变化。
- 主窗口状态球预览右侧显示当前状态。悬浮窗可见时显示「正在悬浮中」，因全屏临时隐藏时显示「全屏隐藏中」，关闭时显示「未开启悬浮窗」。

## 非目标与兼容边界

沿用 Windows、.NET 8 和 WPF。升级后保留已有的球径、颜色和启动设置，旧版保存的背景透明度从本版起不再应用。主窗口预览和托盘图标不受全屏隐藏影响。

## 已确认事项

| 问题 | 确认结论 | 理由 |
| --- | --- | --- |
| 多屏时按哪个屏幕判断全屏？ | 只在状态球所在屏幕进入全屏时隐藏。另一屏播放全屏视频或运行全屏游戏时保留状态球。 | 避免影响其他屏幕上的使用。 |
| 如何区分全屏和普通最大化？ | 识别覆盖整块显示器的全屏视频、无边框全屏和独占全屏游戏。普通的最大化窗口仍允许显示状态球。 | 全屏隐藏服务于专注场景，日常使用最大化窗口时仍可查看状态球。 |
| 全屏期间，按钮应显示什么？ | 已打开但临时隐藏时，继续显示「关闭悬浮窗」。主动关闭后，退出全屏也不再恢复。在全屏期间请求打开时，先进入打开状态，退出全屏后再显示。 | 按钮反映用户是否启用了悬浮窗，临时隐藏期间也保留主动关闭入口。 |
| 退出全屏恢复时是否播放涟漪？ | 恢复到隐藏前的位置，且不播放涟漪。用户主动打开并立即显示，或启动设置使悬浮窗立即显示时，仍播放定位涟漪。 | 避免自动恢复时反复提示，同时保留主动打开时的定位反馈。 |

## 验收条件

1. 首次使用时「全屏时隐藏」默认开启。切换后立即生效，重启后保留。
2. 同屏全屏视频和全屏游戏可使已打开的悬浮窗隐藏，退出全屏后在原位置恢复。检查普通最大化窗口以及另一屏全屏时的行为。
3. 主动打开、点击「关闭悬浮窗」和右键关闭后，主窗口按钮文案均正确更新。通过启动设置自动打开时，按钮也显示「关闭悬浮窗」。
4. 全屏期间主动关闭后，退出全屏不会恢复。全屏期间请求打开后，退出全屏才显示。
5. 主窗口和悬浮窗的背景层均固定为 50% 透明度，升级前保存过其他值时亦如此。「调整状态球」中仅保留大小和颜色设置。
6. 主窗口预览右侧的状态文字在打开、全屏隐藏、自动恢复及关闭时同步更新。

## 技术设计

- 应用使用悬浮窗实例是否存在表示用户的打开意图，独立维护实际可见状态。按钮文案与状态文字由这两个状态更新。
- 设置开启且存在悬浮窗时定期检查该窗口所在的屏幕。使用 Windows 窗口边界和全屏 Direct3D 状态识别全屏，普通最大化按窗口样式和边界处理。隐藏前关闭定位提示，恢复时复用窗口和位置。[Windows 窗口边界](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute) · [Windows 全屏状态](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ne-shellapi-query_user_notification_state)
- 在现有用户设置中保存全屏隐藏开关。背景不透明度使用固定值，旧透明度数据无需迁移。
