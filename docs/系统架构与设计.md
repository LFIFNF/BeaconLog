# 系统架构与设计

## 记录和分类

持久化对象的 `Categories` 数组保存可用分类及匹配顺序。`Entries` 数组沿用原记录顺序，每条记录可带 `Category`，其中 `Id` 是分类标识，`Name` 是记录当时保存的名称。`Guid.Empty` 对应首位的「普通」。旧记录缺少 `Category` 时按「普通」读取。

选择「仅影响以后」时只更新 `Categories`。选择「应用于历史」时，按相同标识更新记录的分类快照。重命名保留标识，删除并应用于历史时改为「普通」。重新添加同名分类会分配新标识。

## 备份与恢复

历史导出的 `Entries` 包含已保存的记录和其分类快照。完整备份另包含 `Journal` 和 `Settings`，前者沿用现有记录文件结构，后者保存启动选项、外观、颜色规则、悬浮位置和自动备份开关。启用开机自启时，使用当前程序路径生成 Windows 登录项。

恢复流程在记录锁内保存恢复前副本，然后按选择写入设置和记录。记录文件原子替换失败时回滚已写的注册表值。若当前记录文件已损坏，恢复前副本通过 `UnreadableHistory` 保存原始字节，其设置仍可以恢复。

恢复设置前，在备份目录持久化 `pending-restore.json`。标记记录恢复前副本名称、是否恢复了历史范围和原 Windows 登录项。写入成功后清除标记。若进程在标记清除前中断，下次启动先在记录锁内回滚选定范围，再打开主界面。

记录增删改、导出、自动备份和恢复的文件 I/O 通过应用的后台队列串行执行。自动备份复用同一天内已比较过的未变文件状态。记录文件仍按完整 JSON 快照替换。
