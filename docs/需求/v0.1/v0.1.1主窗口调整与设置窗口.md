# 主窗口调整与设置窗口

**状态：已确认**

## 背景与目标

BeaconLog 当前的 Windows 主窗口是白色界面原型，包含状态球、「记事本」标题、两个静态入口及带文本提示的区域。本轮精简主窗口，并让用户能通过「设置」打开独立窗口。

## 范围与行为

- **主窗口**保留白色主题和顶部状态球。移除整个记事区，包括边框及「点击此处添加文本」提示。在状态球所在的顶部区域下方加一条横向分割线，线下区域留白。
- 将原「记事本」标题替换为文案为「调整悬浮窗」的按钮。保留现有「打开悬浮窗」入口。
- 将「设置」改为可点击的按钮。点击后打开标题为「设置」的独立 Windows 窗口，沿用白色主题，可通过系统关闭按钮关闭。

## 非目标与边界

本轮范围限于两个窗口的界面、设置入口及设置窗口的开关。记录编辑与保存、按间隔切换状态球颜色、悬浮窗功能和设置持久化均留待后续需求。沿用现有 Windows、.NET 8 和 WPF 项目环境，无需数据迁移。

## 已确认事项

| 问题 | 确认结论 | 理由 |
| --- | --- | --- |
| 设置窗口首版放哪些内容？ | 先采用白色空白内容区，保留「设置」标题和系统关闭按钮。 | 当前尚未定义设置项，可先验收打开和关闭流程。 |
| 设置窗口打开后，主窗口能否继续操作？重复点击如何处理？ | 使用非模态窗口，同一时间只打开一个实例。再次点击时激活已有窗口，关闭后可重新打开。 | 用户可以在两个窗口间切换，也能避免重复弹窗。 |
| 「调整悬浮窗」点击后是否执行操作？ | 本轮保留普通按钮样式，点击暂不触发操作。「打开悬浮窗」沿用当前静态行为。 | 本轮明确要求的交互是打开设置窗口，悬浮窗的调整规则可后续定义。 |

## 验收条件

1. 打开主窗口后，白色界面显示状态球、「调整悬浮窗」按钮、「打开悬浮窗」入口和「设置」按钮。
2. 顶部区域下方有一条横向分割线，线下留白。界面上没有原记事区的边框或文本提示。
3. 点击「设置」后，打开标题为「设置」的独立白色窗口。通过系统关闭按钮关闭后，可从主窗口再次打开。
4. 设置窗口开启期间主窗口可操作。再次点击「设置」时激活已有窗口，屏幕上只有一个设置窗口。
5. 设置窗口内容区留白。「调整悬浮窗」点击后及「打开悬浮窗」入口均不触发操作。

## 技术设计

主窗口持有一个设置窗口引用。首次点击时以主窗口为所有者打开非模态设置窗口，后续点击恢复最小化状态并激活该窗口。设置窗口关闭时清除引用，主窗口关闭时由 WPF 关闭其所属窗口。
